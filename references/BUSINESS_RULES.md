# 六主体合并利润表业务规则

本文档是合并利润表计算口径的唯一权威来源。工作流必须按确定性路径完整执行；去年同期必须由去年主体利润表和去年销售台账重新计算，禁止读取或复制去年最终合并报表。

## 1. 统一输入契约

首次运行只接受：

- `year`：目标年度，必须显式提供；
- `month`：目标月份，范围为1～12；
- `source_dir`：包含全部原始资料的统一来源目录；
- `output_root`：运行产物根目录；
- `thread_id`：稳定且唯一的LangGraph运行标识。

`source_dir` 中必须能够自动识别本年和去年普通四主体利润表、按期间政策要求的美国利润表、本年科技与阳原逐月开票、本年与去年销售台账，以及唯一的正式报表 `.xls` 模板。

`output_root` 不得位于 `source_dir` 内部，防止历史输出被后续预检误识别为输入。

缺少字段、月份越界或类型错误时，输入模型在Graph启动前拒绝请求。文件是否存在、唯一、期间正确和内容可解析由 `preflight` 检查。

## 2. 主体与利润表资料

普通四主体为仁恒科技、阳原仁恒、上海分公司和仁恒化工。必须分别提供本年和去年同期目标月份且唯一的一份利润表。

新疆公司当前不参与资料识别和校验，其利润表项目、本月及累计金额统一按 `0.00` 处理，不产生警告或审核项。

美国分公司是否需要利润表，由本年和去年各自的期间政策决定，不得定义为固定必需或固定可选。

利润表文件必须为 `.xls` 或 `.xlsx`，文件名包含“报表”、主体、年度和可解析期间。工作表标题或前五行必须能识别“利润表”；表头必须唯一识别项目、本月金额和本年累计金额。营业收入、营业成本、营业利润、利润总额和净利润必须存在且金额可解析，禁止将空值或公式缓存缺失静默转换为零。

## 3. 美国期间政策

### 3.1 一般规则

| 目标月份 | 美国确认期间 | 是否要求美国文件 |
|---|---|---|
| 1～2月 | 尚无已确认季度 | 不要求 |
| 3～5月 | Q1/3月 | 要求 |
| 6～8月 | Q2/6月 | 要求 |
| 9～11月 | Q3/9月 | 要求 |
| 12月 | Q4/12月 | 要求 |

预检应排除晚于目标月份的文件，并严格识别确认期间对应的唯一美国利润表。需要美国文件时，缺失、重复、期间不符或累计金额不可解析均直接 `FAILED`。

```text
季末月份（3、6、9、12月） → 美国本月金额和累计金额均纳入
非季末月份                 → 美国本月金额为0，累计取最近确认季度
```

例如目标月份为7月时，需要Q2/6月美国利润表；美国本月为0，累计取Q2累计。

### 3.2 2025年历史例外

美国分公司从2025年6月开始有可用数据。目标期间为2025年1～5月时：

- 不要求、也不识别美国利润表；
- 即使目录中存在美国Q1或其他早期文件也不得纳入；
- 不产生缺失警告或期间审核项；
- 美国本月收入、累计收入和美国自销均为 `0.00`；
- 科技→美国扣减为 `0.00`。

从2025年6月起恢复一般规则。本年与去年同期必须分别生成期间政策。

## 4. 预检门禁

`preflight` 是只读硬门禁，必须完成：

1. 扫描统一来源目录并分类本年、去年资料；
2. 检查普通四主体利润表的完整性、唯一性和目标期间；
3. 根据两年的期间政策识别并校验美国文件；
4. 不识别、不校验新疆文件；
5. 校验利润表工作表、表头、关键科目和金额；
6. 校验本年科技、阳原1月至目标月逐月开票文件；
7. 校验本年、去年销售台账存在且唯一；
8. 校验销售台账的月份、销方、购方、金额和数电票号码字段；
9. 校验并唯一识别 `.xls` 模板；
10. 生成已选文件清单及本年、去年输入指纹。

预检只有两种结果：

```text
全部通过 → 创建本次运行目录并开始M1～M7
任一不通过 → FAILED，不生成业务底稿和正式报表
```

不设置warning、review item或“可继续但需审核”的预检结果。

## 5. 利润表标准化（M2）

- 金额统一使用两位小数 `Decimal`；
- 独立“研发费用”行直接取数；
- “研究费用”为管理费用缩进明细时，从管理费用中拆出；
- 美国管理费用主项本月和累计均为零时，不将其研究费用明细单列；
- 投资收益主项和“其中”明细累计，不允许相互覆盖；
- 解析结果按本年、去年分别保存，作为恢复点。

## 6. 本年计算分支（M3～M5）

科技、阳原营业收入采用开票口径：

```text
开票口径收入 = 有效开票金额 - 设备发票金额
```

设备票通过“信息汇总表”的货物或应税劳务名称识别，并按整票从营业收入和内部销售中排除。

本年M3：

```text
科技、阳原营业收入 ← 开票扣设备口径
其他主体营业收入   ← 利润表
所有主体其他科目   ← 利润表
美国               ← 按期间政策纳入
新疆               ← 0.00
```

本年M4内部销售必须同时满足销方属于集团、购方属于集团且二者不同。内部销售按本月、累计和销方保存明细及来源证据；M4只识别内部销售，不直接修改结果。

```text
本年最终营业收入 = M3抵销前营业收入 - M4集团内部销售
```

销售台账不得在M5形成过程中静默改写营业收入。

## 7. 去年同期计算分支（M3～M5）

去年其他科目由去年主体利润表重新汇总。利润表营业收入仅保留为审计参考，不作为去年最终营业收入。

```text
去年境内台账基数 = 去年销售台账中境内集团销方合计（排除美国销方）

去年最终营业收入
= 去年境内销方销售台账基数
- 去年科技→美国
+ 去年美国利润表营业收入
```

- 本月台账取目标月，累计台账取1月至目标月；
- 科技→美国本月仅季末取本季度范围，非季末为零；
- 科技→美国累计截至美国确认月；
- 美国本月只在季末纳入，累计取确认期间利润表；
- 2025年1～5月科技→美国和美国利润表收入均为零；
- 去年普通内部销售为零；
- 去年阳原自销直接取去年销售台账中阳原销方金额。

禁止读取去年最终合并报表，禁止从本年目录回退取去年资料。

## 8. 营业成本与M6指标

本年和去年均在最终营业收入确定后倒挤营业成本：

```text
营业成本 = 最终营业收入
         -（税金及附加 + 销售费用 + 管理费用 + 研发费用 + 财务费用
            - 投资收益 - 公允价值变动收益 + 营业利润）
```

资产减值损失不参与该公式。

M6基于当前M5结果计算毛利、毛利率、营业净利率、税前利率、主营业务成本率、阳原自销及美国自销等模板辅助数据。分母为零时比率留空。M6只生成预览和指标底稿，不生成正式 `.xls`。

人工修正营业收入后，必须重新倒挤营业成本并重新执行M6。

## 9. M7独立校验与发布分支

M7必须生成本年本月、本年累计、去年本月和去年累计四组严格零差异校验。

```text
本年差异 =（本年M5最终营业收入 - 美国利润表营业收入）
         -（本年集团销售台账 - 美国购方内部销售）

去年差异 =（去年M5最终营业收入 - 美国利润表营业收入）
         -（去年境内销方台账基数 - 科技→美国）
```

新疆当前在M5及M7均按零，不需要额外扣除。差异必须严格等于 `0.00`，不设置容差。

```text
四组差异全部为0.00 → publish_report
任意一组差异不为0.00 → prepare_difference_review → review_and_correct_revenue → interrupt
```

M7本身是唯一发布门禁，不再设置独立 `publish_gate`。

## 10. 差异分析

只有M7存在非零差异时才执行差异分析。

### 10.1 本年主体差异拆分

```text
主体M5收入贡献 = M3主体采用收入 - M4该主体作为销方的内部销售
主体台账校验金额 = 台账中该主体销方金额 - 该主体销售给美国购方的内部销售
主体差异 = 主体M5收入贡献 - 主体台账校验金额
```

- 本月只取目标月，累计取1月至目标月；
- 科技、阳原即使主体差异为零也必须列示；
- 两主体未覆盖的集团差异列为“其他主体/未定位”；
- 各主体影响之和必须严格勾稽对应集团差异；
- 主体拆分只用于定位，不能替代集团M7。

### 10.2 无票销售归因

数电票号码字段标准化后严格等于“无票销售”才计入证据。本月仅汇总目标月，累计汇总1月至目标月；去年归因排除美国销方。证据保留年度、月份、范围、销方、购方、票号、金额、源文件、工作表和源行号。

```text
D = M7差异
U = 同范围无票销售金额
R = D + U
```

- `R=0` 且 `U≠0`：完全解释；
- `U≠0` 且 `|R|<|D|`：部分解释；
- 其他：未解释。

无票归因只是审核证据，禁止自动调整营业收入。

## 11. 人工审核、暂停与恢复

差异材料生成完毕后，工作流设置 `workflow_status = WAITING_REVIEW`，随后 `review_and_correct_revenue` 调用 `interrupt()`。`interrupt()` 前不得生成文件、修改金额或执行其他非幂等副作用。

人工审核差异材料后，通过同一 `thread_id` 提交：

```json
{
  "reviewed_by": "财务人员",
  "reason": "差异原因和修正依据",
  "corrected_revenue": {
    "current_month": null,
    "current_cumulative": "正确金额",
    "prior_month": null,
    "prior_cumulative": null
  }
}
```

只填写存在差异的范围。提交值必须是绝对的正确营业收入，禁止使用加减调整额。

恢复后必须：

1. 验证人工输入结构、审核人、原因和金额；
2. 重新计算本年、去年输入指纹；
3. 指纹变化时立即 `FAILED`，禁止沿用旧Checkpoint；
4. 保存修正前营业收入和M7差异；
5. 将人工确认的绝对收入写入对应M5结果；
6. 重新倒挤营业成本；
7. 追加本轮审核历史；
8. 重新执行M6和M7。

若M7仍有差异，则增加 `review_round`，生成下一轮独立审核材料并再次暂停。不同轮次材料不得相互覆盖。

恢复使用同一 `thread_id`，不会从START重新执行期间政策、预检和原始M1～M5；只从发生中断的节点恢复并重算修正后的下游步骤。

## 12. 发布规则

正式 `.xls` 只能由 `publish_report` 生成，且本年本月、本年累计、去年本月、去年累计四组M7差异必须全部为 `0.00`。

不存在以下发布方式：

- 审批覆盖非零差异；
- 确认保留差异并允许发布；
- `PASS_WITH_APPROVAL`；
- 带残差发布正式报表。

发布成功后：

```text
workflow_status = SUCCEEDED
formal_report = 正式.xls路径
```

M7有差异时：

```text
workflow_status = WAITING_REVIEW
formal_report = null
```

## 13. 失败规则

以下问题直接 `FAILED`：必需输入缺失或重复；应提供的美国文件缺失、重复或期间不正确；利润表、开票或台账Schema错误；关键金额无法解析；模板错误；人工恢复输入不合法；暂停期间输入指纹变化；计算、底稿写入、Checkpoint或正式发布异常。

```json
{
  "workflow_status": "FAILED",
  "formal_report": null,
  "error": {
    "node": "发生错误的节点",
    "type": "稳定错误类型",
    "message": "具体原因"
  }
}
```

M7非零不是失败，而是等待人工审核。

## 14. 状态与产物

工作流状态只使用 `RUNNING`、`WAITING_REVIEW`、`SUCCEEDED` 和 `FAILED`。

主要产物：

- `M1_资料及期间确认/`；
- `M2_单体数据及研发拆分/`；
- `M3_抵销前六主体汇总/`；
- `M4_内部销售/`；
- `M5_抵销后合并结果/`；
- `M6_指标及模板回填/01_经营指标计算结果.csv`；
- `M7_销售台账校验/01_销售台账营业收入校验.csv`；
- `M7_销售台账校验/review_round_NN/03_差异审核清单.xlsx`；
- `M7_销售台账校验/review_round_NN/05_主体销售台账差异拆分.csv`；
- `M7_销售台账校验/review_round_NN/06_人工修正记录.json`；
- 零差异后生成的正式 `.xls`；
- `run_status.json`。

Graph State只保存必要原始值和产物路径，不保存Workbook、DataFrame或大批量明细对象。
