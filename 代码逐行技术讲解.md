# 仁恒合并利润表工作流：代码逐行技术讲解

## 阅读方法

仓库自有代码约三千多行。如果把每个第三方库（FastAPI、LangGraph、openpyxl、xlrd）的内部源码也逐行展开，内容会变成第三方项目源码说明。因此本文件采用下面的范围：

- 项目自有入口、网页、数据库、服务层：按代码行和代码块解释；
- LangGraph 编排脚本：按类、State、节点函数和关键语句解释；
- `renheng_profit`：按模块和函数解释每一步财务处理；
- 第三方库：只解释当前代码调用它之后产生的效果。

核心阅读顺序是：

```text
run_local_web_app.py
  → renheng_web/app.py
  → renheng_web/service.py
  → langgraph_profit_workflow.py
  → renheng_profit/*.py
```

## 二、文件一：`run_local_web_app.py`

文件路径：`scripts/run_local_web_app.py`

### 2.1 文件头

```python

"""启动单机版仁恒合并利润表网页工作台。"""
from __future__ import annotations

import argparse
from pathlib import Path
```

逐行含义：

| 代码 | 作用 |
| --- | --- |
| `#!/usr/bin/env python3` | 在类 Unix 环境中说明使用 Python 3 执行；Windows 主要作为注释存在。 |
| 模块字符串 | 说明这个文件是本地网页工作台的启动脚本。 |

这里没有导入 FastAPI 或 LangGraph。这样做的好处是：解析帮助信息时不要求所有业务依赖都已经导入。

逐行含义：

| 代码 | 作用 |

| `-> argparse.ArgumentParser` | 声明返回值是参数解析器。 |

### 2.3 `main()`

```python
def main(argv: list[str] | None = None) -> int:
    args = build_parser().parse_args(argv)
    try:
        import uvicorn
        from renheng_web.app import create_app
    except ImportError as error:
        raise SystemExit(
            "缺少网页依赖，请先执行：python -m pip install -r requirements.txt"
        ) from error
    uvicorn.run(create_app(args.data_root), host=args.host, port=args.port)
    return 0
```

逐行含义：

| 代码 | 作用 |
| --- | --- |
| `def main(...)` | 定义启动主函数；`argv=None` 表示默认读取 PowerShell/命令行参数。 |
| `build_parser().parse_args(argv)` | 先构造参数规则，再把命令行文本解析成 `args`。 |
| `try` | 尝试加载网页所需依赖。 |
| `import uvicorn` | 导入 ASGI 服务器，真正负责监听端口。 |
| `from renheng_web.app import create_app` | 导入项目自己的 FastAPI 工厂函数。 |
| `except ImportError` | 如果依赖没有安装，就进入统一错误提示。 |
| `raise SystemExit(...) from error` | 打印可读错误并结束进程，同时保留原始异常原因。 |
| `create_app(args.data_root)` | 创建 FastAPI 应用和 `WorkflowService`。 |
| `uvicorn.run(...)` | 启动本地 HTTP 服务；这行会持续运行，直到用户按 `Ctrl+C`。 |
| `return 0` | 服务正常退出时返回成功码。 |

### 2.4 Python 文件入口保护

```python
if __name__ == "__main__":
    raise SystemExit(main())
```

只有直接执行这个文件时，`__name__` 才等于 `"__main__"`，因此才启动服务器。被其他模块导入时不会自动启动服务器。

### 3.3 `create_app()` 初始化

### 3.6 创建任务和上传文件

```python
    @app.post("/api/runs")
    async def create_run(
        year: int = Form(...),
        month: int = Form(...),
        operator: str = Form(...),
        files: list[UploadFile] = File(...),
    ) -> dict[str, Any]:
        try:
            return service.create_run(year=year, month=month, operator=operator, uploads=files)
        except (ValueError, OSError) as error:
            raise HTTPException(status_code=400, detail=str(error)) from error
        finally:
            for upload in files:
                await upload.close()
```

逐行和执行顺序：

1. `@app.post("/api/runs")` 注册创建任务接口；
2. `async def` 是异步路由，因为上传文件关闭操作是异步的；
3. `year/month/operator` 从 multipart 表单读取；
4. `files` 从 multipart 文件字段读取，可以有多个文件；
5. `service.create_run(...)` 负责编号生成、目录创建和文件写入；
6. `ValueError/OSError` 被转换为 HTTP 400，页面能看到错误原因；
7. `finally` 无论成功或失败都关闭上传文件临时流。

## 四、文件三：`renheng_web/database.py`

### 4.1 模块说明和连接方法

```python
class RunRepository:
    def __init__(self, database_path: Path) -> None:
        self.database_path = database_path
        self.database_path.parent.mkdir(parents=True, exist_ok=True)
        self._initialize()

    def _connect(self) -> sqlite3.Connection:
        connection = sqlite3.connect(self.database_path, timeout=30)
        connection.row_factory = sqlite3.Row
        return connection
```

逐行含义：

- `RunRepository`：应用运行记录的数据库访问对象；
- `database_path`：例如 `data/app.sqlite`；
- `mkdir(..., parents=True)`：数据库父目录不存在时自动创建；
- `_connect`：每次操作创建一个短连接；
- `timeout=30`：数据库暂时被占用时最多等待 30 秒；
- `row_factory=sqlite3.Row`：查询结果既能按下标也能按列名读取。

### 4.2 建表和兼容升级

```python
    def _initialize(self) -> None:
        with self._connect() as connection:
            connection.execute("""
                CREATE TABLE IF NOT EXISTS workflow_runs (...)
            """)
            columns = {
                row[1]
                for row in connection.execute("PRAGMA table_info(workflow_runs)").fetchall()
            }
            if "preflight_status" not in columns:
                connection.execute(
                    "ALTER TABLE workflow_runs ADD COLUMN preflight_status TEXT NOT NULL DEFAULT 'NOT_RUN'"
                )
            if "preflight_result" not in columns:
                connection.execute(
                    "ALTER TABLE workflow_runs ADD COLUMN preflight_result TEXT"
                )
```

关键点：

1. `CREATE TABLE IF NOT EXISTS` 只在表不存在时建表，不会删除旧记录；
2. `workflow_runs` 是网页任务索引，不是 LangGraph 内部 Checkpoint 表；
3. `thread_id TEXT NOT NULL UNIQUE` 保证一个线程编号不会被两个业务任务占用；
4. `PRAGMA table_info` 读取已有表结构；
5. 两个 `ALTER TABLE` 让旧版 `app.sqlite` 可以平滑增加预检字段。

主要字段含义：

| 字段 | 含义 |
| --- | --- |
| `run_id` | 业务任务主键 |
| `thread_id` | LangGraph Checkpoint 键 |
| `status` | 网页任务状态 |
| `source_dir` | 上传输入目录 |
| `output_root` | Graph 输出根目录 |
| `run_output_dir` | Graph 实际运行目录 |
| `formal_report` | 正式报表路径 |
| `preflight_result` | JSON 字符串形式的预检结果 |
| `created_at/updated_at/completed_at` | 生命周期时间 |

### 4.3 `create_run()`、`get()`、`list()`

```python
    def create_run(self, *, run_id: str, thread_id: str, year: int, month: int,
                   operator: str, source_dir: Path, output_root: Path) -> dict[str, Any]:
        now = datetime.now().isoformat(timespec="seconds")
        values = {
            "run_id": run_id,
            "thread_id": thread_id,
            "year": year,
            "month": month,
            "operator": operator,
            "status": "DRAFT",
            "source_dir": str(source_dir),
            "output_root": str(output_root),
            "run_output_dir": None,
            "formal_report": None,
            "error_message": None,
            "preflight_status": "NOT_RUN",
            "preflight_result": None,
            "created_at": now,
            "updated_at": now,
            "completed_at": None,
        }
```

这段先在 Python 中组装一整行默认值：新任务从 `DRAFT` 开始，尚未有实际 Graph 输出目录、正式报表和完成时间。

```python
        with self._connect() as connection:
            connection.execute("""
                INSERT INTO workflow_runs (...)
                VALUES (:run_id, :thread_id, ...)
            """, values)
        return values
```

- `with` 结束时自动提交成功事务，异常时自动回滚；
- SQL 使用命名参数，避免把值直接拼进 SQL；
- 返回 `values`，服务层可以把它直接返回给前端。

```python
    def get(self, run_id: str) -> dict[str, Any] | None:
        with self._connect() as connection:
            row = connection.execute(
                "SELECT * FROM workflow_runs WHERE run_id = ?", (run_id,)
            ).fetchone()
        return None if row is None else dict(row)
```

`?` 是 SQLite 参数占位符；找不到任务返回 `None`，找到则把 `sqlite3.Row` 转成普通字典。

```python
    def list(self, limit: int = 50) -> list[dict[str, Any]]:
        with self._connect() as connection:
            rows = connection.execute(
                "SELECT * FROM workflow_runs ORDER BY created_at DESC LIMIT ?", (limit,)
            ).fetchall()
        return [dict(row) for row in rows]
```

按创建时间倒序返回最近 50 条任务，供网页运行记录使用。

### 4.4 `update()` 的白名单机制

```python
    def update(self, run_id: str, **fields: Any) -> dict[str, Any] | None:
        allowed = {
            "status", "run_output_dir", "formal_report", "error_message", "completed_at",
            "preflight_status", "preflight_result",
        }
        updates = {key: value for key, value in fields.items() if key in allowed}
```

调用方可以传多个关键字，但只有 `allowed` 中的列才会更新。这可以防止把任意用户输入当成 SQL 列名。

```python
        updates["updated_at"] = datetime.now().isoformat(timespec="seconds")
        assignments = ", ".join(f"{key} = :{key}" for key in updates)
        updates["run_id"] = run_id
        with self._connect() as connection:
            connection.execute(
                f"UPDATE workflow_runs SET {assignments} WHERE run_id = :run_id", updates
            )
        return self.get(run_id)
```

这里动态生成的只有白名单列名，实际值仍使用命名参数。每次更新自动刷新 `updated_at`，最后重新读取数据库返回最新行。

## 五、文件四：`renheng_web/service.py`

这是网页层和 LangGraph 之间的核心适配层。它解决的不是财务公式，而是任务生命周期。

### 5.1 初始化

```python
class WorkflowService:
    def __init__(self, data_root: Path) -> None:
        self.data_root = data_root.resolve()
        self.runs_root = self.data_root / "runs"
        self.runs_root.mkdir(parents=True, exist_ok=True)
        self.app_repository = RunRepository(self.data_root / "app.sqlite")
        self.checkpoint_path = self.data_root / "langgraph_checkpoints.sqlite"
        with sqlite3.connect(self.checkpoint_path):
            pass
        self._executor = ThreadPoolExecutor(max_workers=1, thread_name_prefix="profit-workflow")
        self._graph_lock = RLock()
        self._connection: sqlite3.Connection | None = None
        self._graph: Any | None = None
```

逐行作用：

| 代码 | 作用 |
| --- | --- |
| `data_root.resolve()` | 把数据根目录变成绝对路径。 |
| `runs_root` | 所有业务任务的父目录。 |
| `mkdir` | 自动创建任务目录。 |
| `RunRepository(...)` | 初始化 `app.sqlite` 和运行索引表。 |
| `checkpoint_path` | 指定 LangGraph Checkpoint 文件位置。 |
| `sqlite3.connect(...): pass` | 先创建空数据库文件；真正的 Checkpoint 表由 LangGraph 创建。 |
| `ThreadPoolExecutor(max_workers=1)` | 只允许一个任务实际执行。 |
| `RLock()` | 保护 Graph 的执行和状态读取。 |
| `_connection/_graph=None` | Graph 依赖懒加载，初始不构建。 |

### 5.2 `_ensure_graph()`：第一次使用时构建 Graph

```python
    def _ensure_graph(self) -> Any:
        if self._graph is not None:
            return self._graph
        try:
            from langgraph.checkpoint.sqlite import SqliteSaver
            from langgraph_profit_workflow import build_workflow
        except ImportError as error:
            raise RuntimeError(
                "网页服务需要 LangGraph 依赖，请先执行 python -m pip install -r requirements.txt"
            ) from error
        self._connection = sqlite3.connect(self.checkpoint_path, check_same_thread=False)
        self._graph = build_workflow(SqliteSaver(self._connection))
        return self._graph
```

执行含义：

1. 如果 Graph 已构建，直接复用，避免每次请求重新编译；
2. 在函数内部导入 LangGraph，延迟依赖检查；
3. 缺少依赖时抛出业务可读的 `RuntimeError`；
4. `check_same_thread=False` 允许线程池工作线程使用 SQLite 连接；
5. `SqliteSaver(connection)` 把 Graph State 持久化到 SQLite；
6. `build_workflow(...)` 返回绑定 Checkpoint 的 Compiled Graph。

### 5.3 文件名和上传写入


```python
    @staticmethod
    def _safe_filename(filename: str) -> str:
        name = Path(filename or "upload.bin").name
        name = re.sub(r"[^0-9A-Za-z一-龥._()（） -]", "_", name).strip(" .")
        if not name or name in {".", ".."}:
            raise ValueError("上传文件名无效")
        return name
```

逐行作用：

- `Path(filename).name` 丢弃用户传入的父目录，只保留文件名；
- 正则表达式把不在允许范围内的字符替换成下划线；
- `strip(" .")` 去除首尾空格和句点；
- 空文件名或 `.`、`..` 直接拒绝。

```python
    def _write_uploads(self, input_dir: Path, uploads: Iterable[Any], *, allow_overwrite: bool) -> list[str]:
        uploaded: list[str] = []
        for upload in uploads:
            filename = self._safe_filename(getattr(upload, "filename", ""))
            if filename in uploaded:
                raise ValueError(f"上传文件重名：{filename}")
            target = input_dir / filename
            if target.exists() and not allow_overwrite:
                raise ValueError(f"上传文件重名：{filename}")
            content = upload.file.read()
            if not content:
                raise ValueError(f"上传文件为空：{filename}")
            target.write_bytes(content)
            uploaded.append(filename)
        return uploaded
```

这个函数不理解 Excel 内容，只负责安全地把上传流写成文件。`allow_overwrite=False` 用于新任务，`True` 用于 DRAFT 状态补传/替换。

### 5.6 `_preflight_state()` 和 `preflight()`

```python
    def _preflight_state(self, row: dict[str, Any]) -> dict[str, Any]:
        from langgraph_profit_workflow import determine_period_policy, preflight

            "year": row["year"],
            "month": row["month"],

            "output_root": row["output_root"],
        }
        policy_state = {**base, **determine_period_policy(base)}
        return {**policy_state, **preflight(policy_state)}
```

这是网页预检和 Graph 预检共用逻辑的关键。网页服务只组装状态，不复制财务检查规则。

```python
    def preflight(self, run_id: str) -> dict[str, Any]:
        row = self._require_run(run_id)
        if row["status"] not in {"DRAFT", "FAILED"}:
            raise ValueError(f"当前状态不能预检：{row['status']}")
        self.app_repository.update(run_id, status="VALIDATING", error_message=None)
```

先确认任务存在并且允许预检，然后把网页状态改成 `VALIDATING`。

成功分支会把选定文件、输入指纹写入 `preflight.json` 和数据库，并恢复为 `DRAFT/PASSED`。异常分支不会启动 Graph，而是把错误写入 `preflight_result`，恢复为 `DRAFT/FAILED`，让财务人员补文件。

### 5.7 `start()`：把首次计算放入队列

```python
    def start(self, run_id: str) -> dict[str, Any]:
        row = self._require_run(run_id)
        if row["status"] not in {"DRAFT", "FAILED"}:
            raise ValueError(f"当前状态不能启动：{row['status']}")
        if row.get("preflight_status") != "PASSED":
            row = self.preflight(run_id)
            if row.get("preflight_status") != "PASSED":
                raise ValueError(row.get("error_message") or "资料预检未通过")
        self.app_repository.update(run_id, status="QUEUED", error_message=None)
        self._executor.submit(self._invoke_start, row)
        return self.get_status(run_id)
```

逐行逻辑：

1. 读取任务记录；
2. 只有 DRAFT 或失败后重试可以启动；
3. 如果之前没有通过预检，先自动预检；
4. 预检不通过则不进入 Graph；
5. 写入 `QUEUED`；
6. 把真正计算提交到单线程执行器；
7. 立即返回当前状态，HTTP 请求不需要等待整套 Excel 计算完成。

### 5.8 `resume()`：恢复中断任务

```python
    def resume(self, run_id: str, correction: dict[str, Any]) -> dict[str, Any]:
        row = self._require_run(run_id)
        if row["status"] != "WAITING_REVIEW":
            raise ValueError(f"当前状态不能恢复：{row['status']}")
        self.app_repository.update(run_id, status="QUEUED", error_message=None)
        self._executor.submit(self._invoke_resume, row, correction)
        return self.get_status(run_id)
```

恢复必须严格要求 `WAITING_REVIEW`。这可以防止用户重复点击恢复按钮，或在任务尚未暂停时提交修正。

### 5.9 `_config()` 和 `_invoke_start()`

```python
    def _config(self, row: dict[str, Any]) -> dict[str, Any]:
        return {"configurable": {"thread_id": row["thread_id"]}}
```

LangGraph 通过 `configurable.thread_id` 区分不同工作流实例。这个配置是首次调用和恢复调用都必须使用的同一个值。

```python
    def _invoke_start(self, row: dict[str, Any]) -> None:
        self.app_repository.update(row["run_id"], status="RUNNING")
        try:
            from langgraph_profit_workflow import ProfitWorkflowInput

            workflow_input = ProfitWorkflowInput(
                year=row["year"],
                month=row["month"],
                source_dir=Path(row["source_dir"]),
                output_root=Path(row["output_root"]),
            )
            with self._graph_lock:
                result = self._ensure_graph().invoke(
                    workflow_input.model_dump(mode="json"), config=self._config(row)
                )
            self._sync_result(row, result)
        except Exception as error:
            self._record_failure(row, error)
```

执行过程：

- 先把业务索引状态改为 `RUNNING`；
- 从数据库行构造 Pydantic 输入对象；
- `model_dump(mode="json")` 把 `Path` 等对象转换为可序列化字典；
- 获取 Graph 锁，避免多个线程同时操作同一个 SQLite Checkpoint；
- 调用绑定 `thread_id` 的 Graph；
- 正常结束进入 `_sync_result`，异常进入 `_record_failure`。

### 5.10 `_invoke_resume()`

```python
    def _invoke_resume(self, row: dict[str, Any], correction: dict[str, Any]) -> None:
        self.app_repository.update(row["run_id"], status="RUNNING")
        try:
            from langgraph.types import Command

            with self._graph_lock:
                result = self._ensure_graph().invoke(
                    Command(resume=correction), config=self._config(row)
                )
            self._sync_result(row, result)
        except Exception as error:
            self._record_failure(row, error)
```

和首次执行的区别只有输入对象：首次是初始工作流输入，恢复是 `Command(resume=...)`。Graph 根据同一个 `thread_id` 找到暂停 Checkpoint。

### 5.11 `_sync_result()`

```python
    def _sync_result(self, row: dict[str, Any], result: Any) -> None:
        state = self._state(row)
        if isinstance(result, dict) and result.get("__interrupt__"):
            status = "WAITING_REVIEW"
        else:
            status = state.get("workflow_status", result.get("workflow_status", "RUNNING"))
```

- `_state(row)` 读取 Graph 当前 Snapshot；
- Graph 返回 `__interrupt__` 说明节点暂停，业务状态设置为 `WAITING_REVIEW`；
- 没有中断时从 State 或返回值读取 `SUCCEEDED/FAILED` 等状态。

```python
        updates: dict[str, Any] = {"status": status}
        if state.get("run_output_dir"):
            updates["run_output_dir"] = state["run_output_dir"]
        if state.get("formal_report"):
            updates["formal_report"] = state["formal_report"]
        if status in {"SUCCEEDED", "FAILED"}:
            updates["completed_at"] = datetime.now().isoformat(timespec="seconds")
        self.app_repository.update(row["run_id"], **updates)
```

这段只把页面需要的摘要写入 `app.sqlite`，不会把完整 Graph State 再复制一份到应用数据库。

### 5.12 失败和状态读取

```python
    def _record_failure(self, row: dict[str, Any], error: Exception) -> None:
        self.app_repository.update(
            row["run_id"],
            status="FAILED",
            error_message=f"{type(error).__name__}: {error}",
            completed_at=datetime.now().isoformat(timespec="seconds"),
        )
```

后台异常不会让线程悄悄消失，而是记录异常类型和消息，并把任务标为 `FAILED`。

```python
    def _state(self, row: dict[str, Any]) -> dict[str, Any]:
        try:
            with self._graph_lock:
                snapshot = self._ensure_graph().get_state(self._config(row))
            return dict(snapshot.values)
        except Exception:
            return {}
```

读取 Snapshot 也使用同一把锁；如果 Graph 尚未初始化或读取失败，返回空字典，让网页仍能显示应用数据库中的状态。

### 5.14 `artifact_path()` 的安全检查

```python
    def artifact_path(self, run_id: str, key: str) -> Path:
        row = self._require_run(run_id)
        state = self._state(row)
        path_text = state.get("artifacts", {}).get(key)
        if not path_text:
            raise FileNotFoundError(f"产物不存在：{key}")
        path = Path(path_text).resolve()
        run_dir = self.runs_root.joinpath(run_id).resolve()
        if run_dir not in path.parents or not path.is_file():
            raise FileNotFoundError("产物路径无效")
        return path
```

核心安全点是 `run_dir not in path.parents`。即使 State 中出现了一个绝对路径，也必须位于当前任务目录下，不能下载任务目录之外的文件。

### 8.3 指纹函数

```python
def _fingerprint(paths: list[Path], policy: dict[str, Any]) -> str:
    digest = hashlib.sha256()
    digest.update(core.input_fingerprint(paths).encode("ascii"))
    digest.update(core.RULE_VERSION.encode("utf-8"))
    digest.update(json.dumps(policy, ensure_ascii=False, sort_keys=True).encode("utf-8"))
    return digest.hexdigest()
```

指纹不是只哈希文件名，而是组合：


## 十二、网页服务调用 Graph 的代码逻辑

当前已经移除独立的工作流命令行入口。Graph 只由网页服务的 `WorkflowService` 调用；网页服务本身仍可通过 `run_local_web_app.py` 启动。

### 12.1 `_ensure_graph()`

`service.py` 在第一次开始计算或恢复时调用 `_ensure_graph()`：

```python
self._connection = sqlite3.connect(
    self.checkpoint_path,
    check_same_thread=False,
)
self._graph = build_workflow(
    SqliteSaver(self._connection)
)
```

这里打开 `data/langgraph_checkpoints.sqlite`，把 SQLite 连接包装成 LangGraph Checkpointer，再通过 `build_workflow()` 编译包含 M1-M7 节点、条件分支和 `interrupt/resume` 的 Graph。编译后的对象保存在 `self._graph`，后续请求复用它。

### 12.2 首次启动 `_invoke_start()`

用户点击网页“开始计算”后，`service.start()` 先把 `app.sqlite` 中的任务改为 `QUEUED`，再提交后台执行器。后台线程执行：

```python
result = self._ensure_graph().invoke(
    workflow_input.model_dump(mode="json"),
    config={"configurable": {"thread_id": row["thread_id"]}},
)
```

`workflow_input` 提供年度、月份、输入目录和输出目录；`thread_id` 用来定位这条工作流的 Checkpoint。Graph 随后按固定边执行期间策略、预检、M1-M7 和发布/审核分支。

### 12.3 审核恢复 `_invoke_resume()`

网页提交审核修正后，Service 使用同一个 `thread_id` 调用：

```python
result = self._ensure_graph().invoke(
    Command(resume=correction),
    config={"configurable": {"thread_id": row["thread_id"]}},
)
```

LangGraph 根据 Checkpoint 找到上一次 `interrupt()` 的位置，把人工修正交给审核节点校验，然后继续执行 M6、M7。网页服务最后通过 `_sync_result()` 将 Graph 结果摘要更新到 `app.sqlite`。

## 十四、前端页面的技术逻辑

`index.html` 是单页页面。它不是另一个后端，而是通过 `fetch()` 调用 FastAPI。

创建任务：

```javascript
fetch('/api/runs', {
  method: 'POST',
  body: new FormData(event.target)
})
```

`FormData` 自动把年度、月份、经办人和文件组成 multipart 请求。

状态轮询：

```javascript
const response = await fetch(`/api/runs/${currentRun}`);
const data = await response.json();
```

页面根据 `data.workflow_status` 决定显示：

- 开始按钮；
- 审核表单；
- 正式报表下载链接；
- 错误信息。

审核输入框根据非零差异动态生成：

```javascript
input[data-revenue-key="current_month"]
input[data-revenue-key="current_cumulative"]
```

轮询时使用 `data-signature` 保存当前差异范围；如果范围没有变化，就不重建输入框，避免用户输入金额时失去焦点。

## 十五、调试时应该从哪里看

### 页面打不开

先看 `run_local_web_app.py` 和 Uvicorn 启动输出，确认端口和依赖。

### 上传失败

看 `app.py → create_run()`，再看 `service.py → _write_uploads()`。

### 预检失败

看 `service.py → preflight()`，再定位 `langgraph_profit_workflow.py → preflight()` 中具体检查。

### 计算结果异常

按顺序检查：

```text
M2 JSON → M3 CSV → M4 汇总/明细 → M5 CSV → M6 预览 → M7 CSV
```

### 恢复失败

重点检查：

1. `app.sqlite` 中的状态是否为 `WAITING_REVIEW`；
2. `thread_id` 是否和首次运行相同；
3. `corrected_revenue` 是否填写了所有非零范围；
4. 输入文件是否在暂停后被修改；
5. Checkpoint 数据库是否仍在原位置。

## 十六、最终理解

这套代码不是“一个脚本从头跑到尾”，而是五层协作：

```text
FastAPI       负责接收请求
Service       负责任务生命周期
LangGraph     负责可恢复的流程状态机
renheng_profit负责确定性财务计算
文件/SQLite   负责证据和状态持久化
```

因此，一次审核恢复的本质不是重新打开一个新程序，而是：

```text
同一个 run_id
同一个 thread_id
同一个 Checkpoint
同一批输入文件
从 interrupt 后继续执行
```
